## Jak odzyskać usuniętą gałąź

```sh
git clone https://github.com/Jozzpoly/ReflexBrain-Lab.git
cd ReflexBrain-Lab
git fetch --tags
git switch -c recover-r1 refs/tags/archive/reflexbrain-2026-11-10/experiment/r1-paired-reason-head-v1
```

To przykładowe odtworzenie dawnego brancha R1, w tym wszystkich jego przodków. Dla innego eksperymentu podmień ostatnią część znacznika na nazwę z JSON.

**Nie usuwaj zbioru archiwalnych tagów**. Same SHA zapisane w JSON nie chronią przed późniejszym odśmiecaniem nieosiągalnych obiektów Git. Tag na GitHubie też nie jest niezależnym backupem poza GitHubem.

**Szczególnie łatwe błędy interpretacji:**
- Pole `archiveTag` w JSON jest *zaprojektowaną nazwą tagu*, także dla 15 zachowanych branchy. **Istnieje dokładnie 100 tagów** — tylko dla usuniętych gałęzi. Dla pozostałych używaj istniejących nazw branchy i ich pełnych SHA.
- W łańcuchu 10 otwartych PR-ów dziewięć porównań head/base jest wprost `ahead`. **PR #70** (`world-ecology-d0`) ma `diverged`: 21 commitów ahead i **1 commit behind** względem bazy `research/living-organism-runtime-a-2026-10-08`. To nie jest utrata kodu, ale zakaz mechanicznego merge/rebase bez analizy tego jednego rozjazdu.
- Po zamknięciu historycznych PR-ów zachowane są różnice, komentarze GitHub i kod pod tagami. **Komentarze PR/CI ani wygasające artefakty nie wchodzą jednak do samego `git clone`**. [Mapa badań](../BADANIA.md) przenosi najważniejsze rozstrzygnięcia do repozytorium, lecz nie stanowi kopii całej korespondencji.
- Nie przeprowadzono kompletnego ponownego audytu bezpieczeństwa pełnej historii 100 branchy, ręcznego testu Windows przez Ownera ani niezależnego backupu poza GitHubem. Te rzeczy pozostają odrębnymi granicami, nie wolno dorabiać do nich PASS.
